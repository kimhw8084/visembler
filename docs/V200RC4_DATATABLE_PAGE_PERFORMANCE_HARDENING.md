# Company UI 2.0.0rc4 — DataTable Page Performance Hardening

RC4 corrects the performance diagnosis from RC3. The reported problem was not primarily the AG Grid vertical scrollbar; the entire `/data` lab page felt heavy.

## Root cause

The DataTable certification route eagerly mounted four independent AG Grid applications at once: the primary 320-row enterprise table, an editable grid, a server-backed grid and a master/detail grid. The server grid also initiated its intentional 180 ms synthetic request during page entry. The page's sticky translucent/blurred lab control bar composited above these complex grid layers.

This created avoidable browser layout/paint/compositor work even while the user was simply scrolling the page.

## RC4 changes

1. Keep the primary enterprise DataTable live immediately.
2. Mount editable, server and master/detail certification surfaces only on explicit user request, exactly once.
3. Preserve every secondary component and behavior; this is workload scheduling, not feature removal.
4. Preserve RC3's immediate AG Grid scroll settings because they are safe, while no longer presenting them as the primary page-lag fix.
5. Disable backdrop blur for the sticky lab control bar only on `/data`, using the existing opaque Company elevated surface instead.
6. Add `contain:layout` to the DataTable shell to isolate grid layout work from the rest of the page.
7. Ensure deferred grids inherit the currently selected lab density.
8. Add browser certification for initial AG Grid count, page-scroll frame latency and explicit deferred-surface completeness.

## Non-regression contract

- search/sort/filter/resize/select/export/row-actions/sparklines remain unchanged on the primary table;
- editable rollback behavior remains available;
- server latest-request-wins behavior and 180 ms synthetic delay remain available;
- master/detail, saved presets and expandable-row anatomy remain available;
- global theme, density and motion controls remain functional;
- RC3 grid virtualization and immediate-scroll defaults remain in force.

## Source validation

RC4 source validation is generated by `company-ui-source-certify`; target-runtime/browser/human gates remain mandatory before stable `2.0.0`.
